# Лабораторна робота 0 — синтаксис Java

![tests](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/Java-Fall2026/{{REPO}}/badges/badge.json)

## Що потрібно встановити

1. **JDK 21.** Перевірте, чи вже встановлено:

   ```
   java -version
   ```

   Якщо ні — поставте
   [Temurin 21](https://adoptium.net/temurin/releases/?version=21).

2. **Git.** Перевірте: `git --version`.

Окремо встановлювати Gradle **не потрібно** — у проєкті є wrapper,
який завантажить потрібну версію сам.

IDE не обов'язкова, але з нею зручніше: IntelliJ IDEA Community
або VS Code з розширенням Extension Pack for Java.

## Як почати

```
git clone https://github.com/Java-Fall2026/lab0-<your-username>.git
cd lab0-<your-username>
./gradlew test
```

У Windows замість `./gradlew` пишіть `gradlew.bat`.

Перший запуск триває довго — Gradle качає себе і залежності.
Тести впадуть, і це нормально: методи ще не написані.

## Що треба зробити

У файлі `src/main/java/ua/university/BasicOperators.java` реалізуйте
всі методи. Зараз вони повертають `null`, `0` або `false` — це заготовки.

Читайте javadoc над кожним методом: там описано, що метод повертає,
які межові випадки враховані і коли треба кинути виняток.
Якщо javadoc чогось не описує — питайте, це моя недоробка.

## Як перевірити себе

```
./gradlew test
```

Запускайте після кожного написаного методу, не в кінці.

Побачити, який саме тест впав і чому:

```
./gradlew test --info
```

Детальний звіт відкривається у браузері:
`build/reports/tests/test/index.html`

## Що не можна змінювати

Файл `src/test/java/ua/university/BasicOperatorsTest.java` — це тести.
Не редагуйте його. Якщо здається, що тест хибний — напишіть мені,
можливо ви маєте рацію.

Сигнатури методів у `BasicOperators` теж не змінюйте: назви,
параметри й типи повернення мають лишитися такими, як є.
Всередині методів пишіть як вважаєте за потрібне.

## Як здати

1. Запуште свій код:

   ```
   git add .
   git commit -m "lab 0"
   git push
   ```

2. Відкрийте вкладку **Actions** у своєму репозиторії на GitHub.
   Там автоматично запуститься перевірка. Зелена галочка — тести пройшли.

3. На захисті покажіть, що `./gradlew test` проходить **на вашому
   комп'ютері**, а не тільки на GitHub.

Останній пункт і є справжнім змістом цієї роботи. Код тут простий
і його неважко отримати звідки завгодно — а от робоче середовище
на своїй машині доведеться підняти самостійно.

## Якщо щось не працює

- `./gradlew: Permission denied` (macOS/Linux) — виконайте `chmod +x gradlew`
- `JAVA_HOME is not set` — JDK не встановлено або не в PATH
- Помилки з кодуванням у виводі (Windows) — виконайте `chcp 65001`
- Не збирається після встановлення JDK — перезапустіть термінал

Не витрачайте на це більше пів години наодинці — пишіть.
